# Spark Track 项目说明

## 1. 项目定位

Spark Track 是一个运行在 Obsidian 里的插件，目标不是再做一个复杂的任务系统，而是把「灵感收集、日常待办、目标推进、卡点处理」统一进一个移动优先的侧边栏工作台里。

它适合的场景是：

- 平时大量想法和任务都先记在 Obsidian
- 既想快速捕获，又不想把笔记写乱
- 希望把长期目标拆成可推进、可回顾、可复盘的结构
- 希望任务和进度记录尽量贴近 Markdown 文件本身，而不是藏在黑盒数据库里

插件在 `manifest.json` 中的描述是：

> A mobile-first sidebar console for capture, tasks, and goal tracking inside Obsidian.

## 2. 核心能力

### 2.1 闪念捕获

用户可以在侧边栏里直接输入内容，作为一条 capture 写入当日笔记。

支持两种输入方式：

- 直接输入普通文本，作为闪念进入 Inbox
- 使用轻命令输入，例如：
  - `/todo 买充电线`
  - `/goal 做一个书籍 TTS 工具`
  - `/red 书籍 TTS 工具 | API 限流卡住`
  - `/green 今天解决方案验证通过`

同时支持给 capture 打标签或情绪 chip，例如想法、复盘、心情等。

### 2.2 Inbox 二次分拣

最近 7 天的 capture 会进入 Inbox 列表，默认最多展示 12 条。每条记录都带有处理状态，支持：

- 保留为笔记
- 转成日常任务
- 转成目标任务
- 转成目标进度记录

这个设计的重点是：先收，再分。降低记录阻力，再把信息导向正确位置。

### 2.3 双轨任务系统

插件把任务分成两类：

- 日常任务
- 目标任务

日常任务可以写入：

- 当日 Daily Note
- 单独的全局待办 Markdown 文件

目标任务则写入目标索引文件里的受控区块。任务本质上仍然是 Markdown 任务行，插件只是负责增删改查和状态同步。

### 2.4 战略目标管理

每个目标会在目标根目录下自动创建独立文件夹，并生成一个 `_Index_*.md` 索引文件。

目标索引文件包含两层核心信息：

- Frontmatter 中的目标元数据与进度追踪数据
- 文档正文中的目标任务区块与时间线区块

目标支持：

- 新建目标
- 添加目标任务
- 提交黄灯 / 绿灯 / 红灯进度
- 记录卡点解除
- 归档目标

### 2.5 进度雷达与卡点闭环

插件会根据目标追踪数据自动生成：

- aged blockers：持续未解决的红灯卡点
- suggestions：当天优先建议动作

建议优先级大致是：

1. 先处理长期未解决的卡点
2. 再推动已有目标任务
3. 最后提醒长期沉默的目标补一笔进度

这让插件不只是“记录工具”，而是带一点轻量运营逻辑的执行面板。

## 3. 信息落盘方式

Spark Track 的一个关键思路，是把数据尽量写回用户自己的 Markdown 文件，而不是维护独立数据库。

### 3.1 Daily Note

capture 和部分日常任务会写进 Daily Note。

插件会优先读取：

- Obsidian 官方 Daily Notes 配置
- Periodic Notes 的 daily 配置

如果都没有，则回退到插件自己的设置：

- 默认目录：`Daily`
- 默认格式：`YYYY-MM-DD`

### 3.2 全局待办文件

如果用户把日常任务目标改成全局文件，插件会写入一个 Markdown 文件，默认是：

- `全局待办.md`

### 3.3 目标目录

目标默认写入：

- `Goals/`

每个目标会有自己的文件夹，里面至少包括：

- `_Index_目标名.md`
- 按日期生成的进度记录文件，例如 `2026-04-15-进展.md`

## 4. 数据结构设计

项目的核心类型定义集中在 `src/types.ts`。

主要实体包括：

- `CaptureEntry`：闪念记录
- `ManagedTask`：插件管理的任务
- `TrackerEntry`：目标进度记录
- `GoalSummary`：目标聚合视图
- `AgedBlocker`：老化卡点
- `NexusSuggestion`：推进建议

从结构上看，这个插件不是简单的 UI 壳，而是把 capture、task、goal、tracker、blocker、suggestion 几类对象串成了一个闭环。

## 5. UI 与交互设计

前端使用 Svelte 5，主视图挂在 Obsidian 自定义右侧面板里。

界面主要分成 5 个区域：

- 闪念输入台
- Inbox
- 推进雷达
- 双轨控制台
- 战略目标阵列

整体交互特征是：

- 以侧边栏为核心，不强依赖大页面
- 面向移动端和窄宽度布局
- 以折叠面板组织信息层次
- 以弹窗完成目标创建、进度提交、卡点解决

## 6. 技术栈

项目采用：

- TypeScript
- Svelte 5
- Vite 5
- Obsidian Plugin API

构建命令见 `package.json`：

- `npm run build`
- `npm run check`

构建后会通过 `scripts/copy-build.mjs` 把 `dist/main.js` 和 `dist/styles.css` 复制到仓库根目录，以符合 Obsidian 插件的产物形式。

## 7. 目录结构

项目当前的主要目录含义如下：

- `src/`
  - 插件源码主目录
- `src/services/`
  - 业务服务层，负责 Daily Note、Goal、Task 的文件读写与聚合
- `src/ui/`
  - Svelte 界面
- `src/ui/components/`
  - 复用组件，如折叠区块、目标卡片、任务列表
- `src/utils/`
  - Markdown 区块、frontmatter、路径、安全写入等工具函数
- `src/view/`
  - Obsidian 自定义视图封装
- `scripts/`
  - 构建辅助脚本
- `dist/`
  - 构建产物目录
- `archive/v1/`
  - 旧版本源码归档，保留历史实现参考

## 8. 安全与边界控制

这个项目有一个比较成熟的设计点：它没有默认相信用户输入的路径，而是做了明确的写入安全限制。

`src/utils/safe-write-paths.ts` 会阻止插件把数据写到这些位置：

- `.git`
- `.obsidian/plugins`
- `node_modules`
- 开发工作区下的 `src/`、`dist/`、`scripts/`

同时也会阻止把目标路径设置成源码文件，例如：

- `.ts`
- `.js`
- `.svelte`
- `.css`
- `.json`

这意味着插件在“自动写文件”这个高风险动作上，已经有了比较明确的保护边界。

## 9. 当前版本特点

从当前代码来看，这一版 Spark Track 已经具备比较完整的闭环能力：

- 能快速收集
- 能把 capture 转成任务或进度
- 能管理长期目标
- 能识别未解决卡点
- 能给出当日推进建议
- 能把核心数据稳定写回 Markdown

它更像一个“Obsidian 内的个人执行控制台”，而不是单一的待办插件。

## 10. 适合对外介绍的亮点

如果要对外介绍，这个项目最值得讲的点有 5 个：

- 它把闪念、任务、目标、复盘做成了一个工作流，而不是几个孤立功能
- 它基于 Markdown 文件本体工作，数据可见、可迁移、可手改
- 它强调移动优先的侧边栏体验，适合随手记、随手分拣
- 它有“卡点雷达”和“推进建议”，不是被动记账式插件
- 它在写入路径上做了安全约束，避免误写到源码目录或插件目录

## 11. 一句话总结

Spark Track 是一个面向 Obsidian 的轻量执行系统：先捕获，再分拣，再推进，再复盘，让日常任务和长期目标都能落在用户自己的 Markdown 工作流里。
