# 2026-04-24 移动端目标任务调试记录

## 1. 背景

本次工作集中处理 Obsidian Android 端 `Spark Track` 插件里“目标任务”相关的移动端稳定性问题，重点是：

- 新增任务后，笔记文件已写入，但侧边栏 UI 不即时更新
- 任务拖动排序后，笔记文件顺序已变化，但侧边栏 UI 不即时更新
- 删除和勾选在移动端也需要可用、可控、尽量稳定

用户通过 Android 模拟器和真机式操作持续复现问题，并反馈现象。

## 2. 主要问题现象

### 2.1 新增任务

复现路径：

`打开侧边栏 -> 目标 -> 11111 -> 输入任务名 -> 点添加`

现象：

- 目标笔记文件内已经出现新增任务
- 侧边栏目标卡片里没有立刻显示新增任务
- 重启 Obsidian 后，新任务能出现

结论：

- 不是写入失败
- 是“当前会话 UI 未稳定同步”

### 2.2 拖动排序

现象：

- 任务拖动后，笔记文件里的顺序已正确变化
- 当前侧边栏 UI 仍保留旧顺序
- 重启 Obsidian 后顺序正常

结论：

- 排序落盘成功
- 当前会话里的 UI 仍有旧状态/旧可视区问题

### 2.3 删除 / 勾选

现象：

- 删除和勾选本身能落盘
- 但如果主卡片里直接展示任务列表，移动端依然可能出现旧内容残留或更新时机不稳定

## 3. 过程中的判断与分析

### 3.1 已确认事实

- Obsidian Android 端目标笔记文件是会被正确写入的
- 重启 Obsidian 后，新增、删除、拖动结果都能正确体现
- 说明问题主要不在文件持久化，而在当前会话 UI 同步和移动端可视区/状态链路

### 3.2 根因判断

综合本次排查，问题不是单点，而是几层因素叠加：

1. **文件层正确，UI 层不稳定**
   - 文件已变
   - 当前侧边栏组件未稳定反映最新数据

2. **移动端 WebView 的焦点/滚动/视口行为会放大问题**
   - 输入框 focus/blur
   - 当前可视区锚定
   - Obsidian 移动端右侧栏/侧边栏视图本身的宿主机制

3. **内联拖拽和主卡片任务展示耦合过深**
   - 拖动、滚动、输入、删除、勾选、写文件、刷新事件放在一个区域内
   - 在移动端容易形成“文件对了，但 UI 看起来不对”的结果

4. **历史上的乐观更新和刷新抑制逻辑会干扰排序后的即时反馈**
   - 尤其是 `main.ts` 中 `runGoalTaskMutation` 这条链路，原本是为内联拖拽抖动和闪烁设计的
   - 当排序移到 Modal 后，这套逻辑不再完全适配

## 4. 做过的改动记录

下面这些改动都做过，其中一部分有效，一部分只提供了排查信息，未彻底解决问题。

### 4.1 做过但没有彻底解决的尝试

1. **主卡片内的即时滚动/自动滚动**
   - 新增后尝试把新任务滚进视口
   - 补了延迟滚动、二次滚动、卡片级滚动
   - 结果：对移动端宿主环境不够稳定，不能作为根治方案

2. **新增“最新任务”固定预览区**
   - 试图在输入框下方固定显示最近一条任务
   - 结果：如果主卡片还直接消费任务列表状态，依然可能出现“展示旧状态”的问题

3. **排序后主界面即时刷新**
   - 将 `reorderTasks` 改为直接走 `runAction -> refreshState`
   - 结果：文件刷新链路更直接，但只要主卡片还承担任务列表渲染，仍可能看到旧 UI

4. **保留主卡片内完整任务列表**
   - 即使排序落盘成功，主卡片内显示仍不稳定
   - 结果：判定“主卡片继续直接挂目标任务列表”不是稳妥方案

### 4.2 最后保留并收口的改动

1. **新增独立的目标任务 Modal**
   - 引入 `GoalTaskSortModal`
   - 将任务查看、排序收进独立弹窗

2. **新增独立的 `TaskSortModal.svelte`**
   - 作为目标任务弹窗内容
   - 支持拖拽排序
   - 使用最小拖拽能力子集，不复用主界面复杂列表逻辑

3. **主卡片移除内联任务列表**
   - 目标卡片现在只保留：
     - 新增任务输入框
     - 任务数量
     - `任务列表` 按钮
   - 不再在主卡片直接展示目标任务内容

4. **弹窗内增加删除和勾选**
   - 删除、勾选、排序统一放进弹窗
   - 弹窗内部维护本地任务状态，尽量减少对主卡片刷新时机的依赖

5. **排序保存使用更直接的链路**
   - `reorderTasks()` 改为走 `runAction(() => taskService.reorderTasks(tasks))`
   - 不再对排序使用旧的 `applyGoalTaskReordered` 本地补丁

6. **增加 Android 部署脚本**
   - 新增 `scripts/deploy-android.ps1`
   - 方便反复将构建结果推送到模拟器的 Obsidian 插件目录中

## 6. 当前解决思路

当前收口思路不是继续修“主卡片里的任务列表刷新”，而是直接规避这个高风险点：

### 主卡片职责

只负责：

- 展示目标基础信息
- 提交新增任务
- 展示任务总数
- 提供 `任务列表` 入口

### 任务弹窗职责

负责：

- 查看全部任务
- 拖动排序
- 勾选完成
- 删除任务

这样做的理由：

- 主卡片不再承担复杂任务列表展示
- 任务相关的重交互都在局部弹窗内完成
- 可以显著降低移动端 UI 同步复杂度

## 9. 本次工作的工程结论

这次问题的关键结论是：

**移动端目标任务在当前插件结构下，不适合继续在主卡片中直接承载完整任务列表。**

原因不是“文件写不进去”，而是：

- 宿主环境是 Obsidian Android + WebView
- 焦点、滚动、侧边栏视图、文件变更事件共同作用
- 会导致“数据正确但 UI 当场看起来不正确”

因此，本次采取的最终方向是：

**将重交互任务列表移入独立 Modal，主卡片只保留轻量入口和摘要信息。**
